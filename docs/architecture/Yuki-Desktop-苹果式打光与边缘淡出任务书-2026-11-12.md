# Yuki Desktop 苹果式打光与边缘淡出任务书

日期：2026-11-12

状态：用户提供 iOS 截图并建议：「我很想学习苹果的打光策略，像是这个蓝色按钮边缘能折射一丝蓝光以及整个界面在上边缘磨砂淡出的效果也值得学，但最值得研究的是他的打光策略与液态玻璃效果，当然，得优化到最佳，延迟降到最低」。本任务书即执行依据，基线为 `feat/stickers-and-flow`。

## 1. 截图观察与现状

| 观察（iOS） | 现状 | 处理 |
| --- | --- | --- |
| 灰色圆钮与深色胶囊的边缘光很细，亮在朝光的上缘与对角的下缘，两侧几乎不亮，玻璃显得有厚度 | 光照图只亮朝光一侧，背光边只有 22% 的弱反光；亮带 1.5px、内辉 10px | 光照图改为双侧高光：朝光边最亮，对角边约为其一半，两侧暗；亮带收细到约 1 个显示像素，内辉收到 6px，仍按显示像素抗锯齿 |
| 蓝色按钮边缘是一圈更亮的蓝青色光，像蓝玻璃把光折射出来 | 有色按钮的边缘是白色渐层 | 有色按钮的边缘光取自身色调提亮，指针附近同样是本色的光；内侧沿边一层同色的微光 |
| 内容到顶部时越近边缘越模糊、越淡（磨砂淡出） | 只在滚动后出现，几乎不透明的底色渐层（100%→94%→透明）加 6px 模糊，内容一到顶部就被盖住 | 改为渐进模糊：两层背景模糊，越靠上越强，配合较轻的底色渐层；内容在边缘处模糊变淡而非被盖住 |

延迟：光照图仍按尺寸缓存、只算边带；淡出两层只覆盖顶部约 70px 的条带，滚动时测量帧耗。

## 2. 失败情形（先写，再写代码）

E2E：`glass-quality.spec.ts`、`liquid-glass.spec.ts`、`edge-fade.spec.ts`（新）。

1. 光照图的上边（朝光）不是最亮，或下边（对角）亮度低于上边的 35%，或左右两侧中点不暗于下边。
2. 光照图亮带宽于 2 个显示像素（上边中点往内 3 个显示像素处仍有亮带强度），或边缘有锯齿（最外一像素未按覆盖率衰减）。
3. 有色按钮的边缘光不是自身色调（以蓝色强调色测：边缘像素的蓝通道不高于红通道，或不比按钮底色更亮）。
4. 对话列表滚动后，顶部淡出层不是两层渐进模糊（上层模糊不强于下层），或底色渐层在中部仍不透明（≥ 90%）。
5. 滚动对话时，顶部淡出产生超过 50ms 的长任务。

本任务书修订既有用例：《液态玻璃》第 3–4 条与《对话玻璃》第 16 条原为「背光边只有微弱反光、光沿边框带深入」，改为「对角边亮度为朝光边的 35%–100%，两侧暗，亮线细」。

## 3. 施工中的发现

- 原顶部淡出层是工具栏的负层级伪元素：浏览器中它只能取样工具栏自身内部，捲到下方的内容从未被模糊，起作用的只有底色渐层。现改为工具栏之下两个独立层（强模糊在上、轻模糊与底色在下）。
- 原对话列表从工具栏下缘开始（`.chat` 顶部 52px 留白），内容在工具栏下缘被硬切，不会进入工具栏底下。现把留白移入列表的内边距：列表延伸到顶端，首条消息位置不变，内容捲进工具栏下方后磨砂淡出。
