# Yuki Desktop 全局透明磨砂与统一顶部淡出任务书

日期：2026-11-12

状态：用户反馈「桌面背景我看了，透明效果没出来，而且桌面的透明主题还是『光线』的背景，我认为底层有点毛病」，并要求透明磨砂全局显示（含设定、关于 Yuki），顶部淡出统一用于工作、档案成果、Yuki 的电脑、这台电脑等界面；Yuki 的电脑的「運作中 · 控制：無」移到「接手」左侧，切换显示器时不再顶起。经商量选定：透明磨砂与对话背景拆成两项设定；透明时不画光线纹理；透明度参照访达侧栏。基线为 `main`（#66）。

## 1. 排查结论

| 事实 | 依据 | 处理 |
| --- | --- | --- |
| 系统磨砂被两层底色盖住：整窗底 `.app` 涂 `--mat-ground`（浅 84%、深 88% 不透明），主面板在「桌面」下仍是 45% 本色，合成后浅约 91%、深约 93% 不透明 | `App.module.css` `.app`、`.main`；`tokens.css` `--mat-ground` | 透明磨砂时整窗底不再涂色，侧边栏只留 16% 本色，系统材质直接透出；页面表面只留约 35% 本色，卡片约 40% |
| 「桌面」下对话区仍画光线的细线与弧形，看起来就是光线背景 | `--backdrop-desktop: var(--lens-light)` | 删除「桌面」背景；透明与否由窗口材质决定，对话背景只是叠在对话区的图案，「無」什么都不画 |
| 原 E2E 只量主面板单层透明度，没算下面整窗底，所以通过 | `chat-polish.spec.ts` 只读 `.main` 的 alpha | 改为在网页之下铺两种壁纸，量合成后的像素差：壁纸透不出来即失败 |
| 透明只可能出现在对话区：设定、详情栏、工作／档案／关于等页面与非对话页的工具列都是实色变量 | `--bg-content`、`--bg-inspector` 直接用作页面底 | 页面表面改用 `--surface-page`／`--surface-pane`，透明磨砂时在根上换成半透明本色；卡片 `--bg-raised` 同样变薄 |
| 只有对话页的工具列浮在内容上、有顶部淡出；`scrolled` 由对话页自行回报 | `Workspace` 的 `floating` 只在 `chat`／放大详情；`DisconnectedHome` 传 `floating={false}` | 所有页面工具列都浮起，内容区留出 52px；`Workspace` 在内容区捕获任一贴顶滚动容器的滚动，统一显示淡出层；设定页使用同一淡出组件 |

「永遠不透明」并入「窗口材質：透明磨砂／不透明」（存储仍为 `opaque`）。对话背景选项为「無、光線、極光、晚霞、格線」，已存的 `desktop` 读为「無」（`plain`）。没有系统材质（Linux）、选不透明、减少透明度或增加对比时，全部回到实色。

## 2. 失败情形（先写，再写代码）

E2E：`global-frost.spec.ts`（新）、`chat-polish.spec.ts`、`settings.spec.ts`、`computer-toolbar.spec.ts`、`apple-light.spec.ts`。

1. 透明磨砂且有系统材质时，在网页之下换两种壁纸，侧边栏、主面板（对话、工作、档案成果、关于）、详情栏、设定页任一表面采样点的合成像素差小于壁纸差的 40%（壁纸透不出来）。
2. 透明磨砂时页面表面完全透明（像素差大于壁纸差的 90%），文字底下没有本色。
3. 浅色下页面表面不比壁纸亮，深色下不比壁纸暗（失去浅／深底层逻辑）。
4. 对话背景「無」在透明磨砂下仍有任何图案或底色；其他背景在透明磨砂下仍铺不透明底色。
5. 不透明、无系统材质或增加对比时，任一表面仍透出壁纸（像素差大于壁纸差的 2%）。
6. 外观里没有「窗口材質」，或选择后重开设定不保留；对话背景仍有「桌面」，或已存 `desktop` 读出后不是有效背景。
7. 工作、档案成果、关于、设定：内容未滚动时出现顶部淡出，或滚动后不出现与对话页相同的两层淡出（同一组 `data-edge-fade` 元素）。
8. 未滚动时，任一页面第一个可见内容的顶边高于工具列底边（被工具列遮住）。
9. Yuki 的电脑：在「沙箱」与「QQ 登入」之间切换，切换钮的纵向位置或标题栏高度变化超过 0.5px；状态文字不在「接手」左侧。

## 3. 施工中的发现

- **背景滤镜是叠在原内容之上，不是取代它。** Chromium 把 `backdrop-filter` 的结果画在背后原内容的上面；背后不透明时看不出来，背后半透明（透明磨砂的窗口）时，模糊后的副本本身半透明，清晰的原内容从中透出。实测：真实窗口里一块 `blur(8px)` 盖在标题上，标题仍清晰、只多一圈光晕。这就是「底层透上来」，也会让顶部淡出与所有玻璃失效。处理：所有背景滤镜末尾接同一个静态 SVG 滤镜 `#yuki-backdrop-seal`（透明度 ×8），只在透明磨砂时经 `--seal` 生效：有覆盖的地方变不透明，完全透明处仍透出系统磨砂。代价是玻璃之下取页面本色而非桌面色调（网页本就看不到窗口外的系统磨砂），玻璃读起来像较厚的「常规」玻璃。
- **Yuki 选单的模糊在侧边栏里不起作用。** 选单原是侧边栏（`overflow-y: auto`）里、`z-index: 3` 切换钮内的绝对定位元素，真实 Electron 窗口中它的 `blur` 对背后毫无作用（无头 Chromium 中正常），所以无论有无 seal 都透出侧边栏的字。处理：选单改放顶层（`popover`），用 CSS 锚点定位贴在切换钮下方。（更正，见《液态玻璃组件统一任务书》6.1：当时归因于「滚动容器」不成立——真实窗口中滚动区与正在滚动的设定页里的模糊都有效，同样结构的探针也有效；失效的确切条件未能复现。）
- **「卡一下」是折射在形变结束时才接上。** 原 `sync` 等展开动画结束才生成贴图并挂上折射，于是展开约 600ms 后画面突变。展开动画的最后一帧就带着静止时的圆角，改为一开始就按它生成贴图；真实窗口中打开选单无长任务。
- **「抖一下」是送出途中闪出「狀態未確認」。** 请求已在本进程投递、状态由 draft 变为 submitted 后，`sending` 只对 draft 成立，于是在服务器接收前约 150ms 里，送出的那则多出「狀態未確認 · 查詢」一行（67→95px），随后消失，列表随之回缩 28px，所有消息一起跳动；是否出现取决于网络时序，所以看起来不分位置、时有时无。处理：`sending` 认事实「本进程仍在投递且没有遇到问题」，与状态无关。另观察到一次「正在處理」在同一轮中淡出又淡入（activity 读到一次 idle），本次未处理。
- **焦点框被裁。** 说明框正文可滚动、上下无内边距，最后一个输入框的焦点框底边被切；侧边栏拖拉把手贴窗口全高；电脑工具列的切换钮容器为省略号设了 `overflow: hidden`（标题本身已有）。分别给正文上下各 4px、把手的焦点框画在内侧、删除多余的 `overflow: hidden`。
- 已有用例的修订：`chat-polish` 的「桌面」背景用例由本任务书第 1–5 条（在网页下铺壁纸、量合成像素）取代；`native-materials` 原断言「系统材质只露在侧边栏下、整窗底 84%／88%」，改为整窗底透明、页面表面 35%；`native-toolbar-scroll` 仍读 #66 已删除的工具列 `::before`，改读顶部淡出层。
