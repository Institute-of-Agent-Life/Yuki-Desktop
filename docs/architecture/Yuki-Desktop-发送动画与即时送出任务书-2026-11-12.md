# Yuki Desktop 发送动画与即时送出任务书

日期：2026-11-12

状态：用户看过调研结论后要求「按方案做，第6条也一起做」；施工中又要求「玻璃材质有没有优化空间，你顺手做了」，玻璃部分见 P5。本任务书即执行依据。

## 1. 目标与原则

发消息时，文字从输入框离开、水滴从输入框升起并长成气泡、文字随气泡出现，整个过程是一个连续的物理动作；按下送出的瞬间就有反应，不等网络。

- 禁止防御性编程：动画由仓库已有的弹簧（`motion/spring.ts`）驱动，不另写缓动表；发送沿用现有发件箱、回执、查證流程，不新增状态机。
- 发送顺序的事实不变：本机先记录（`draft`），确认身份与归属后才提交（`submitted`），服务器接收后才是 `accepted`。
- 尊重「减少动态效果」设置：不播放任何发送动画。

## 2. 调研基线与确认的问题

基线：Desktop `origin/main` = `15fda84`。

调研方法：在 renderer 回归页（`renderer-regressions.html?case=conversation-glass`）里暂停动画、逐 40ms 截图，并按 `motion/bubble.ts` 的关键帧数值计算速度曲线。

| 问题 | 证据 | 处理 |
| --- | --- | --- |
| 动画走走停停 | 5 段关键帧各自套 `cubic-bezier(.25,.12,.36,1)`，每段末速度为 0：宽度速度在 120ms 降到 0.05、140ms 跳到 4.2，280ms 降到 0.14、300ms 跳到 3.7 | 一个弹簧驱动全部属性，按 60fps 采样成线性关键帧 |
| 尾巴与运动相反 | 尾巴在 120ms 最长，那时气泡几乎静止；气泡快速变大时尾巴在缩 | 尾巴长度取弹簧当前速度，快则长、停则收 |
| 气泡原地长出，不从输入框出发 | 起点就在最终位置，尾巴指向空处 | 自己的气泡从输入框文字区升到最终位置 |
| 文字被遮罩硬切，偶尔露在玻璃外 | `[data-bubble-copy]` 用同形状 `clip-path` 遮罩，160ms 截图文字被切半、并高出玻璃上沿 | 去掉文字遮罩；文字随气泡移动，按玻璃大小等比缩放并淡入，始终在玻璃内 |
| 输入框文字瞬间消失 | `setDraft('')` 后直接清空，无过渡 | 送出时输入框文字向上淡出 |
| 结尾闪一下 | 动画期间隐藏玻璃 `::before/::after`、显示 SVG 描边，520ms 一次性切回 | 后半段描边淡出、玻璃边缘淡入 |
| 浅色主题下 Yuki 的气泡与背景几乎分不开 | 中性气泡只有 12% 底色，无投影；截图中气泡边缘只靠 1px 线 | 底色提到 22%，静止气泡加柔和投影 |
| 深色主题每个气泡一圈均匀亮描边，像线框 | 边缘色 0.56 不透明；光照用 `abs(n·L)`，上下两边一样亮，左右也有 0.28 底亮度（实测左右各 0.34、下边 0.42） | 光从左上来：迎光边亮、对边只留 0.38 倍反光、侧边底亮度降到 0.1；深色边缘色降到 0.4，环形描边的右下端减半 |
| 按送出后要等网络 | `connections.send` 先 `identify`、`verifyOwner`、`box.send` 全部完成才返回，之后才清空输入框和出现气泡 | 先在本机发件箱记录并立刻返回，确认与提交在后台继续；提交中显示「送出中」 |

## 3. 施工项

### P1 弹簧驱动的水滴（`motion/bubble.ts`、`motion/spring.ts`）

- `springs.bubble`：k 240、阻尼比 0.7（约 4% 过冲，450ms 视觉稳定）。
- 从 0 到 1 模拟一次，按 1/60s 采样；每帧：玻璃轮廓大小取 `min(值, 1)`，尾巴长度取 `max(速度, 0) / 峰值速度`，玻璃不透明度 0.55 起迅速到 1。
- 自己的气泡：`.bubble` 从输入框文字区中心（受列表底部留白限制，至少在输入框范围内）垂直升到原位（`translateY((1-值)·距离)`，过冲时略高于原位再回落）；距离不超过消息列表底部留白，列表不出现新的滚动范围。Yuki 的气泡原地生长，轻微上浮 10px。
- 文字：不再遮罩；以生长角为原点等比缩放到能放进当前玻璃的大小，值 0.55→0.9 之间淡入。
- 结尾：后半段时长内（此时水滴已基本静止）SVG 描边淡出，玻璃 `::before/::after` 淡入（`pseudoElement` 动画），取消原 `[data-liquid]` 隐藏规则。

### P2 输入框文字离场（`releaseDraft`）

送出且草稿被清空的同一时刻，在输入框文字原位置放一层只读副本，180ms 内上移 10px 并淡出后移除。

### P3 对话页接线（`Conversation.tsx`）

- 发送时记下输入框位置，作为气泡起点。
- 气泡启动前先把列表滚到底，再量位置。
- 中途取消（离开底部、搜索等）时取消全部相关动画。

### P4 即时送出（`connections.ts`、`Conversation.tsx`）

- `queue`：先 `identify`（服务器身份与兼容性；连线期间有缓存，平时不等网络）——身份不符照旧拒绝、不动发件箱与草稿；随后本机发件箱以 `draft` 记录、立即返回，`verifyOwner`、`box.send` 在后台继续。离线（`transport_unknown`、`unavailable`）保持 `draft`，与原来一致；归属确认的其他失败记在该条的 problem 上并保持 `draft`，原文不丢。
- 本机连接器任务（`connector-submit`）仍等待同一后台提交完成后返回，其文字说明依赖最终状态。
- 发件箱列表附带 `sending`：`draft` 且正在后台提交。「送出中」显示期间不显示「查詢」。

### P5 玻璃材质（`materials/glass.ts`、`ConversationGlass.module.css`、`Conversation.module.css`）

- 所有玻璃（工具栏、输入框、气泡、开关等）的边缘光照改为有方向：`facing = max(0, n·L) + 0.38·max(0, −n·L)`，底亮度 0.1。
- 对话气泡：中性底色浅色 22%、深色 20%；深色边缘色 0.4；环形描边从左上的边缘色渐变到右下的 45%。
- 静止气泡加投影（浅色蓝灰、深色黑，不透明模式无投影）；入场水滴前半段无投影，到静止形状时随边缘交接一起出现。

## 4. 失败情形（先写，再写代码）

E2E 一：`tests/e2e/conversation-glass.spec.ts`（renderer 回归页，逐帧暂停采样），产物 `send-motion.json`。

1. 气泡升起或长大途中，速度降到峰值的 10% 以下后又加速（走走停停）。
2. 尾巴最长的帧离速度峰值超过 3 帧，或最后一帧仍有尾巴。
3. 自己的气泡第一帧玻璃中心不在输入框（composer）的垂直范围内。
4. 送出后输入框里没有向上淡出的文字副本，或 300ms 后副本仍在。
5. 气泡文字上存在 `clip-path` 动画。
6. 任一帧文字不透明度 > 0.05 时，文字范围超出该帧玻璃范围（1px 容差）。
7. 最后一帧 SVG 描边不透明度 > 0.05，或玻璃边缘不透明度 < 0.95。
8. 动画期间消息列表 `scrollHeight` 变化。
9. 回执在动画途中到达时，气泡元素被替换（沿用）。
10. Yuki 的回复同样违反 1、2、5、6、7 任一条。
11. 开启「减少动态效果」后，送出仍产生气泡动画或文字副本。

E2E 二：`tests/e2e/instant-send.spec.ts`（真实 Electron + 真实后端），产物 `instant-send.json`。

12. 服务器挂起 `/me` 时按送出，1 秒内输入框没有清空、气泡没有出现。
13. 挂起期间该气泡状态不是「送出中」，或出现「查詢」。
14. 放行后没有成为正式消息、出现两条相同消息，或「送出中」没有消失。
15. 送出前断开服务器，气泡不是「連線後送出」。

E2E 一另含玻璃材质（`conversation-glass.spec.ts`，数值写入 `send-motion.json` 的 `rim`）：

16. 气泡边缘光照图中，下边亮度不低于上边的 0.5 倍（原算法 0.63；各平台字体使气泡宽度与光照图分辨率不同，CI 实测 0.46、本机 0.27），或右边不低于左边的 0.6 倍。
17. 静止气泡没有投影；或入场水滴第一帧就带投影、最后一帧没有投影。

### 随 P4 调整的既有测试

- `artifacts`、`backend`、`character-data`、`character-routing`、`first-history-refresh`、`restart`、`windows-character-data`、`workspace-acceptance` 八个 E2E 原先以「输入框清空」为消息已被接收的时点，直接读发件箱要求有 `eventId`；改为 `waitForAcceptedMessage` 等原请求真正被接收。
- `server-settings` 遗失回应一例原先只认 `unknown`；遗失后串流触发的自动查證会因代理挡住回执读取而记为 `unavailable`，两者都是「已提交、未确认」。改为断言 `submitted` 且 problem 为两者之一。
- 单元测试「身份或兼容性不符时不动发件箱与草稿」保持不变并通过（`identify` 仍在记录之前）。
