# Yuki Desktop 聊天细节与玻璃质量任务书

日期：2026-11-12

状态：用户使用 #63 版本后提出：
- 「发消息的时候气泡会卡一下」；
- 「选中消息的蓝色的框会把Yuki的头像也包括进去……只需要包括气泡本身」；
- 「不需要在我发出去的消息下面显示一行已接收，查询，已取得原回执之类的」；
- 「私聊时若调用发送以外的工具不是会强制开一个work吗……那个work不需要在聊天主界面上显示」；
- 「所有的ui边缘都有点粗糙，而且气泡打光很不自然，外面会显现出一个方形的影子」；
- 「这个彩边功能我咋感觉没那么显著呢」；
- 「能不能也允许增添换桌面的入口来更换不同底色然后做实验……这个功能做好了可以留下来」。

本任务书即执行依据，基线为 #64（`feat/message-flow`）。

## 1. 调研结论

| 问题 | 证据 | 处理 |
| --- | --- | --- |
| 发送时卡一下 | 真实 Electron + 后端，#63 与 #64 各连发 3 次：每帧间隔最大 18ms、无长任务。卡顿感来自 #63 的列表单帧跳 106px、提示出现再跳 48px | #64 已改为同一弹簧滑动，不另改 |
| 选中框包住头像 | `.selected` 的 `outline` 画在整条 `article` 上 | 改画在气泡上，外扩 2px |
| 状态行常驻 | `Pending` 对每条自己消息显示「送出中／已接收／已取得原回執」 | 只在需要人处理时显示：离线保存、状态未确认、出现问题 |
| 自动登记的 work 卡片 | 后端调查：私聊首个非 send 工具批次由 `WorkControl.admit_execution` 接纳，与 `manage_task` start 的行完全相同，客户端无从区分 | 后端（Yuki #616）记录 `admission: host_execution`；桌面在聊天主界面不显示这类卡片，「工作」列表照常 |
| 气泡外的方形影子 | 4 倍截图：气泡圆角外有直角矩形明暗差；逐项关闭定位为 `backdrop-filter`。气泡玻璃带外扩边距并以 `clip-path` 裁成圆角，在可滚动列表的合成路径里，背景滤镜只按其外接矩形裁切；单独页面无法复现，仅靠圆角的输入框、工具栏无此问题 | 静止气泡不外扩、不用 `clip-path`，只靠圆角；进场动画期间才外扩并用路径裁切 |
| 边缘粗糙 | 光照图与位移图共用分辨率：气泡 ≤1、输入框约 1 倍 CSS 像素，Retina 上只有 1/3–1/2 精度，弧线有台阶；深色下玻璃外另有 0.5px 深色描边，与内侧亮边形成双线 | 光照图按显示像素比生成并对最外一像素按覆盖率抗锯齿；位移图保持较粗分辨率；深色描边只在增强对比时绘制 |
| 进场后出现第二道亮边 | 光照图在进场时按外扩尺寸生成；`ResizeObserver` 观察内容框，静止后内容框不变而未重绘 | 观察边框盒 |
| 彩边不明显 | 红蓝相对绿只差 ±12%，输入框边缘最大错开约 4px；色散在模糊与压对比之后进行 | 错开 ±32%，浮动玻璃先弯折与色散，再模糊 |
| 没有更换背景的入口 | 对话背景写死在 `.chat` 的样式里（光线 + 两块主题色） | 「设置 → 外观 → 对话背景」五种：光线（原样）、纯色、极光、晚霞、格线，浅深两套配色；存入偏好设置并在重启后保留；不透明模式下仍为实色 |

## 2. 失败情形（先写，再写代码）

E2E `chat-polish.spec.ts`、`glass-quality.spec.ts`、`message-flow.spec.ts`、`instant-send.spec.ts`。

1. 选中消息时 `article` 有外框，或外框没有画在气泡上，或头像落在外框内。
2. 送出中、已接收、已取得原回执时消息下出现状态行；离线保存时没有「連線後送出」。
3. 静止气泡的玻璃使用 `clip-path`、宽度不等于气泡、或圆角不是 18px。
4. 光照图像素尺寸不等于玻璃尺寸乘以显示像素比；进场结束后光照图仍是外扩尺寸。
5. 输入框背景滤镜不以弯折开头，或红、蓝弯折相对绿不是 0.68、1.32。
6. 普通模式下玻璃有可见描边；增强对比模式下没有。
7. 聊天主界面显示了 `admission = host_execution` 的 work 卡片；「工作」列表不显示它；其余 work 卡片消失。
8. 选择对话背景后根元素与对话区背景没有随之改变，或重启后没有保留；任一背景的图层构成与定义不符。
9. 不透明模式下对话区仍显示所选背景。
