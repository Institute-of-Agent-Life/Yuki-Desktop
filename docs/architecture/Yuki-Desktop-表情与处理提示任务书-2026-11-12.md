# Yuki Desktop 表情与「正在處理」任务书

日期：2026-11-12

状态：用户反馈：
- 「桌面端的富媒体还不够完善……现行表情功能没有做到，没法发图片表情」；
- 「发出消息的时候会下拉两次最新位置，只要一次就好」；
- 「Yuki正在处理出现和消失的动画不自然，而且还会让一些顶层的气泡框重新冒泡上去」。

本任务书即执行依据，基线为 `main`（cda6cd1）。后端配套：Yuki #617（App 跨平台目录选图、附件 `sticker` 标记）。

## 1. 调研结论

| 问题 | 证据 | 处理 |
| --- | --- | --- |
| 桌面收不到 Yuki 的表情 | 本机部署：`app` 平台 5 次配图全部 `emoji_no_candidate`，QQ 519 次成功；选图只看 `stickers/app/`（0 张） | 后端 #617：App 跨全部平台目录选图片表情 |
| 表情显示成普通附件 | 表情事件 `text` 为空、`content` 为「[表情: 标签]」，附件按普通图片卡片显示；客户端读不出表情标记 | 契约钉住 #617 的 `sticker`；无正文且附件全为表情的消息以表情显示：无玻璃气泡、无卡片外框、按表情尺寸（最长边 ≤140px，保持比例），标签作为图片名称；进场以同一弹簧放大淡入 |
| 发送时下拉两次 | 真实 Electron + 后端逐帧：51ms 自己的气泡升起，列表 648→730；411ms「正在處理」以气泡液态长出，列表再 730→778 | 提示不再占列表高度：放在最后一条消息下方、输入框上方原有的留白里（留白加 8px），出现与消失只淡入淡出，列表不动 |
| 提示消失时列表反转、上方气泡「重新冒泡」 | 962ms 回复到达开始滑动，1073ms 提示同时收起，列表在 842 处反向退到 812；1557ms 收起后活动状态再次为执行中，提示以全高突然出现，列表停在离底 48px | 同上：提示不改变内容高度，收起和再次出现都只是原位淡入淡出 |

## 2. 失败情形（先写，再写代码）

E2E：`stickers.spec.ts`（新）、`message-flow.spec.ts`。

1. 表情消息仍有玻璃气泡、卡片外框，或显示「[表情: …]」文字。
2. 表情图片最长边超过 140px，或比例被改变。
3. 表情图片没有以标签命名（如「表情：开心」）。
4. 表情到达没有进场动画；减少动态效果时有动画。
5. 普通图片附件（无 `sticker`）按表情显示。
6. 从送出到「正在處理」出现，列表有第二段滚动。
7. 「正在處理」出现或消失时列表内容高度改变，或任何已有消息移动。
8. 「正在處理」出现与消失没有至少 5 帧的淡入／淡出；消失后文字仍在。

本任务书取代《消息全链路动画衔接任务书》中「正在處理」生长与收起的第 4、6 条（提示不再改变列表高度）。
